Turn Loop and Phases

Previous Next

How a match runs - GameState, the phase loop, phase states, ready and sync, timers, the start phase, world layout, snapshots and rejoin

Turn loop and phases

Main objects

  • GameState : NetworkedBehaviour is the match controller, one per match. It holds the players, islands, phase objects, Log, Chat, SnapshotStore, AIPlay, LobbySettings and a match-wide Unity.Mathematics.Random random.
  • Island : NetworkedBehaviour belongs to one player: owner (NetworkedVar<Player>, 0x90), grid (IslandGrid, 0x98), statistics (Statistics, 0xA0: resources and learnt technologies).
  • Player : NetworkedBehaviour: name, colour, skins / civilization, AI state, isDefeated, isAwaited, ping, start-game slot.

Useful GameState fields: players 0xE8, playerIds 0xF8, lobbySettings 0xD0, phaseOrder 0x170, startPhase 0x178, harvestPhase 0x180, disastersPhase 0x188, buildPhase 0x190, combatPhase 0x198, winPhase 0x1A0, turnCounter (NetworkedVar<int>) 0x1B8, TurnPhase 0x1C0, IsTraining 0x1C8.

GameState has Action fields that are good hook points for mods: onIslandSpawned, onStartGame, onEnterPhase, onSyncPhase, onEndGame, onExit(string), onReset, onRejoin, onDisasterLog(Player, StructuredText).

Phase order

GameState.Awake (0x5F26A0) sets

phaseOrder = [ HarvestPhase, DisastersPhase, BuildPhase, CombatPhase, WinPhase ]

StartPhase ("Settle") is not in the loop: it runs once at the start of the match. Awake also seeds random, shuffles the player colours into teams and wraps the lobby settings in a NetworkedVar.

Phase Time limit (timer FAST) Notes
Start ("Settle") 60 s once per match
Harvest 40 s (+5 s sync) Harvest and dice
Disasters none ends when every client has played the animations, Disasters
Build 70 s Build phase
Combat 35 s planning time; the fight is simulated and animated afterwards, Combat
Win none Win conditions

Timer speed (lobby option TimerSpeed): FAST ×1, SLOW ×1.5, UNLIMITED = no limit (TurnPhase.get_TimeLimit 0xFE0460). Games with fewer than two human players are forced to UNLIMITED (GameState.StartGame). The values are fields of the phase components in the scene (timeLimit, timeLimitSync), not code.

Phase states

Each phase is a TurnPhase<TData, TIslandState> with a PhaseState: ACTIVE = 0, SYNC = 1, INACTIVE = 2. For every island the phase holds one PhaseData object (for example BuildData); per-player state is in islandStates (keyed by client id).

GameState.UpdateTurnPhase (0x5F6E20) runs every frame:

  • ACTIVE: when TurnPhase.IsReady() is true, call TurnPhase.Sync().
  • SYNC: when TurnPhase.IsSynced() is true, go to the next phase in phaseOrder whose ShouldSkip() is false. Wrapping from the last phase back to the first increments turnCounter. ChangeTurnPhase (0x5F2C20) calls old.Exit() then new.Enter(false) and flashes the taskbar if the window is not focused (not for a defeated player).

The turn counter goes up when the Win phase wraps back to the Harvest phase.

Ready

TurnPhase.IsReady (0xFDD8B0):

  • For every island: ready = IsReady(island), and Player.IsAwaited = !ready (the "waiting for player" marker).
  • False while the phase banner is still showing (TimeSinceEnter < BannerDuration, 2 s).
  • Otherwise true when all islands are ready, or when the timer ran out (TimeRemaining < 0).
  • An island is ready when its phase data has nothing to do, or the player pressed Ready (PhaseData.Skip() → SkipRPC, flag HasSkipped).

Sync

TurnPhase.Sync (0xFDEB40):

  1. Store syncTime; the server sends SyncRPC(syncTime) to all clients.
  2. Server: for every island owned by an AI, call AIPlay.PlayPhase(phaseData, aiState). The AI makes its moves when the phase ends, not during it.
  3. State = SYNC, fire GameState.onSyncPhase.
  4. Server: ApplyChanges(done). Each phase overrides it to apply the planned actions of all players.

After every phase's ApplyChanges, TurnPhase.Recompute recomputes every island (storage capacity, defeat).

Entering a phase

TurnPhase.Enter (0xFDCD00) runs on every machine. The server tells all clients to enter (EnterRPC with the start time), every island's PhaseData.Enter runs (it also sets the Preview flag, see Build phase), and on clients the phase's interface is enabled. It also sets the time of day: each phase has a timeOfDay field (all phases 0.125 = morning) that is written into the DayNightCycle target, see Rendering.

Clock

ITurnPhase.Time (0x56D8D0) is the clock all phases use. It returns Cheats.NetworkTime(): the network time multiplied by the developer speed factor.

Start phase ("Settle")

StartData.Reset (0x572C40) fills the island's BuildingsToPlace list: Castle, Cottage ×3, Farm, Dock. StartData.PlaceBuilding (0x5728C0) places one of them if the normal tile rules pass (IslandGrid.CanPlaceBuilding) and the type is still in the list; each listed type can be placed exactly as often as it appears.

There is no check for buildings that already exist on the island: an island loaded from an island code that already has a Castle still gets the start Castle, so the player has two.

At the end (StartPhase.ApplyChanges 0x573370), for every island:

  1. Placed buildings are added (if they still fit).
  2. Every type still in BuildingsToPlace is placed automatically at IslandGrid.PlaceableBuilding(type) (0x6179E0). This happens whether the timer ran out or everybody pressed Ready.
  3. The island is recomputed and gets the start resources: 3 food, 3 wood, 2 stone, 4 hammers, 8 culture.

PlaceableBuilding walks the island in a spiral from the centre outwards (the same spiral the AI uses), tries the 4 orientations without mirroring, and takes the first spot where CanPlaceBuilding passes and the building does not raise disease risk (Disease.DoesRiskMoreDisease). So auto-placed buildings end up as close to the island centre as allowed. (The AI places its farms far from the centre on purpose, see AI.)

World layout

GameState.SpawnIslands (0x5F3F70) runs on the server at game start with the match random generator, so the layout is the same for everybody.

Island positions (one per player):

  • g = island grid size (49 × 49 by default), halfDiag = √((g.x/2)² + (g.y/2)²) ≈ 34.6, step = halfDiag × 0.001.
  • Starting at radius r = step, take a random point in an ellipse with radii (r × 16/9, r), turned 45°. Reject it if it overlaps an island already placed (|dx| ≤ g.x and |dy| ≤ g.y); otherwise r grows by step and it tries again. Islands are packed tightly, in a 16:9 oval turned 45°; more players make it wider.
  • The points are sorted by angle around the origin and given to the players in list order, so neighbours in the player list are neighbours around the circle.

Island shapes (fairness): 256 islands are generated and sorted by score (natural resources + build space + cliffs). Only the middle N (N = number of players) are kept and shuffled, so every player gets an island of about median quality. Generation itself: Island generation.

A layout mod can postfix SpawnIslands to move islands or replace grids, but it must run on the host so every client gets the same world.

Snapshots and rejoin

TurnPhase.TakeSnapshot stores (Island, IslandGrid.SyncData, Statistics.SyncData) for every island when a phase is entered; SnapshotStore keeps them under (player, turn, phase). GameState.Restore(), RestoreTurnPhase and Rejoin(Player) let a player who reconnects rebuild the state (PhaseData.RejoinClientRPC).

Training

GameState.IsTraining is the tutorial game (strings training.information.*).
